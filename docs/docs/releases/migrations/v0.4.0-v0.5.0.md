---
title: Migrating from v0.4.0 to v0.5.0
description: What changes in your code when you upgrade from v0.4.0 to v0.5.0, and how to update it.
---

These changes ship in v0.5.0. Everything else in the [v0.5.0 release notes](../v0-5-0) works without changes to your code.

## Renamed and removed types

### `FormFieldProps` is now `FormFieldValidationProps`

The type of the `Form` validation props that every field shares (`errorPattern`, `eagerValidation`, `validateOnInputDelay`) is renamed `FormFieldValidationProps`. `FormFieldProps` is now the props of the new `FormField` component.

```ts
// Before
import type { FormFieldProps } from '@hareui/vue'

type MyFieldProps = { label: string } & FormFieldProps

// After
import type { FormFieldValidationProps } from '@hareui/vue'

type MyFieldProps = { label: string } & FormFieldValidationProps
```

### Icon types

`NavigationMenuIconValue` and `CommandPaletteIcon` are removed. Use `IconValue`, which every icon prop now shares. It's the same type: a class string or a component.

```ts
// Before
import type { NavigationMenuIconValue } from '@hareui/vue'
import type { CommandPaletteIcon } from '@hareui/vue/command-palette'

const navIcon: NavigationMenuIconValue = 'icon-[gravity-ui--house]'
const paletteIcon: CommandPaletteIcon = SearchIcon

// After
import type { IconValue } from '@hareui/vue'

const navIcon: IconValue = 'icon-[gravity-ui--house]'
const paletteIcon: IconValue = SearchIcon
```

### `AutocompleteHighlight` is removed

`Autocomplete`'s `highlight` payload is now typed `ComboBoxHighlight`. It's the same shape: `{ ref, value }`.

```ts
// Before
import type { AutocompleteHighlight } from '@hareui/vue'
// After
import type { ComboBoxHighlight } from '@hareui/vue'
```

## Empty values

### `Input`, `TextArea` and `TextField` can emit `null`

The `update:modelValue` payload is `string | number | null | undefined`, so the field can commit `null` with `v-model.nullable`. A handler typed for `string | number` no longer type-checks.

```ts
// Before
const onUpdate = (value: string | number | undefined) => {
  name.value = String(value ?? '')
}

// After
const onUpdate = (value: string | number | null | undefined) => {
  name.value = String(value ?? '')
}
```

Without a modifier, the values these fields emit are the same as in v0.4.0.

### `CellSelect` and `InlineSelect` emit `null` when cleared

Clearing the selection emits `null` instead of `undefined`, as `Select` does. Check for both, or for `null`.

```vue
<!-- Before -->
<CellSelect
  v-model="status"
  :items="statuses"
  @update:model-value="(v) => v === undefined && reset()"
/>

<!-- After -->
<CellSelect v-model="status" :items="statuses" @update:model-value="(v) => v == null && reset()" />
```

## Focus listeners

`@focus` and `@blur` on `InputOtp` and `NumberField` now listen on the input instead of the wrapper element, so they fire when the input gains and loses focus. To react to focus moving anywhere inside the field, listen with `@focusin` / `@focusout` on an element around it.

```vue
<!-- Before -->
<NumberField v-model="qty" @blur="save" />

<!-- After: same code, fires when the input loses focus -->
<NumberField v-model="qty" @blur="save" />

<!-- To react to focus leaving the whole field, buttons included -->
<div @focusout="save">
  <NumberField v-model="qty" />
</div>
```

## Item icons

Items of `Breadcrumbs`, `Accordion`, `Tabs`, `Dropdown`, `ContextMenu`, `ListBox`, `Select`, `ComboBox` and `Autocomplete` now render their own `icon` field before the label. If you added an `icon` field yourself and drew it in a slot, the item now also renders it: an Iconify name such as `'gravity-ui:house'` shows as an empty box next to your slot's icon. Pass a component or a CSS class and drop the slot code, or rename your field.

```vue
<!-- Before: custom field drawn in the slot -->
<Breadcrumbs :items="[{ label: 'Home', href: '/', icon: 'gravity-ui:house' }]">
  <template #item="{ item }">
    <Icon :icon="item.icon" /> {{ item.label }}
  </template>
</Breadcrumbs>

<!-- After: the item renders the icon itself -->
<Breadcrumbs :items="[{ label: 'Home', href: '/', icon: HouseIcon }]" />
```

## Drawer placement in right-to-left layouts

In right-to-left layouts a `Drawer` with `placement="left"` or `"right"` now docks on that physical side of the screen. Before, it docked on the opposite side while sliding in from the named one. If you swapped the placement to compensate, remove the swap.

```vue
<!-- Before: swapped so the drawer docked on the right in RTL -->
<Drawer :placement="dir === 'rtl' ? 'left' : 'right'" />

<!-- After: placement names the physical side -->
<Drawer placement="right" />
```

## Button as a link

A `Button` with `as="a"` and `href` now keeps native link semantics: no `role="button"`, and Enter activates it instead of Space. To keep button semantics, render a `<button>` and navigate in `@click`.

```vue
<!-- Before: role="button", activated with Space -->
<Button as="a" href="/docs">Docs</Button>

<!-- After: a native link, activated with Enter -->
<Button href="/docs">Docs</Button>

<!-- To keep button semantics -->
<Button @click="router.push('/docs')">Docs</Button>
```

## ComboBox `change` event

In v0.4.0 a `@change` listener on `ComboBox` fell through to the root and caught the input's native `change` event, fired when typed text was committed, with an `Event` argument. `change` is now a component event fired with the new value whenever the value changes: when an option is selected, or when custom text is committed with `allowsCustomValue`.

```vue
<!-- Before: native Event from the input -->
<ComboBox v-model="city" @change="(e) => save((e.target as HTMLInputElement).value)" />

<!-- After: the committed value -->
<ComboBox v-model="city" @change="(value) => save(value)" />
```
