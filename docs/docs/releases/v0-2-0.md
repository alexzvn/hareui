## New

### New components

**Dashboard:** build an app shell with a resizable, collapsible sidebar and panels.

- [DashboardGroup](/docs/components/dashboard-group) holds the sidebars and panels and keeps track of their size and collapsed state.
- [DashboardSidebar](/docs/components/dashboard-sidebar) can be resized and collapsed, and opens as a slideover, drawer or modal on mobile.
- [DashboardPanel](/docs/components/dashboard-panel) holds the main content, with header, body and footer slots.
- [DashboardNavbar](/docs/components/dashboard-navbar) sits at the top of a panel, with the sidebar toggle built in.
- [DashboardToolbar](/docs/components/dashboard-toolbar) adds a second row under the navbar for filters, tabs and actions.
- [DashboardResizeHandle](/docs/components/dashboard-resize-handle), [DashboardSidebarCollapse](/docs/components/dashboard-sidebar-collapse) and [DashboardSidebarToggle](/docs/components/dashboard-sidebar-toggle) resize the sidebar, collapse it on desktop, and open it on mobile.

**Layout:** the building blocks of a page.

- [App](/docs/components/app) wraps your app, providing global configuration and the toast region.
- [Header](/docs/components/header) and [Footer](/docs/components/footer) are responsive.
- [Main](/docs/components/main) fills the viewport height left below the header.
- [Container](/docs/components/container) centers your content and limits its width.
- [Error](/docs/components/error) is a ready-made error page.

**Data and navigation:**

- [RichTable](/docs/components/rich-table) is a data table built on TanStack Table, with sorting, filtering, grouping, pagination and row selection.
- [NavigationMenu](/docs/components/navigation-menu) displays a list of links horizontally or vertically.

### Vite plugin

`@hareui/vue/vite` auto-imports HareUI components in templates through [unplugin-vue-components](https://github.com/unplugin/unplugin-vue-components) and applies app-wide theme overrides at build time.

```ts [vite.config.ts]
import hareui from '@hareui/vue/vite'

export default defineConfig({
  plugins: [vue(), tailwindcss(), hareui({ prefix: 'H' })],
})
```

- `prefix` lets you write `<HButton>` or `<h-button>`.
- `ui` sets theme overrides below `createHareUI({ ui })`.
- `HareUIResolver({ prefix })` plugs into an existing unplugin-vue-components setup.

See [Frameworks](/docs/getting-started/frameworks#vite-plugin-optional).

### Form schema validation

`Form` validates a reactive `state` with any [Standard Schema](https://standardschema.dev) (Zod, Valibot, ArkType, Yup, Effect Schema, …) or a Superstruct struct, with a form-level `validate` function, or both.

```vue
<Form :schema="schema" :state="state" @submit="onSubmit" @error="onError">
  <TextField v-model="state.email" name="email" label="Email" />
</Form>
```

- Errors appear on the field whose `name` matches, by exact name or by the field's `error-pattern`.
- `@submit` fires once validation passes, with the schema's output as `event.data`. `@error` gets `event.errors`, and each error carries its control's `id` so you can focus it.
- `validate-on`, `validate-on-input-delay` and the field prop `eager-validation` control when a field is validated as the user types and leaves it.
- A `nested` form is validated together with its parent form.
- `loading-auto` disables the fields while an async `@submit` runs.
- The form ref (`FormInstance`) exposes `validate`, `submit`, `clear`, `getErrors`, `setErrors`, and dirty, touched and blurred field tracking.

A form without `state`, `schema` or `validate` still submits natively, as before.

See [Form](/docs/components/form#schema-validation).

## Changes

- `<Form disabled>` disables every form control inside it, including sliders, color pickers and date pickers. A `Fieldset` inside a disabled `Fieldset` or `Form` is disabled too.
- `createHareUI({ portal })` sets the portal target for every overlay at once. A component's own `portal` prop still wins. See [Portal Target](/docs/getting-started/quick-start#portal-target).
- Theme tokens and Tailwind properties now work inside shadow roots.

## Bug Fixes

- **Modal, AlertDialog, Drawer:** the dialog title stays accessible when you use the content slot. Full-size modals no longer zoom.
- **Theme:** a light scope nested inside a dark one can opt out of the dark variant.
- **ToastProvider:** forwards attributes to the toast region.
- **ColorSlider:** no longer touches `Element` during SSR.
